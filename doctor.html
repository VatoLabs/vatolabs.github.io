so101-doctor

A free tool for the SO-101 robot arm. It checks how your six servos are set up and writes a twin: a simulated copy of the arm for the free MuJoCo simulator, built for the servo gain your arm runs. On our arm the twin came to rest about twice as close to the real arm as the stock model (one arm, not yet replicated). It only reads: it cannot move the arm or change a setting.

# In a terminal on macOS or Linux, with Python 3.10 or newer: make a private Python folder
$ python3 -m venv ~/so101
# Install the tool and MuJoCo into it
$ ~/so101/bin/pip install https://github.com/VatoLabs/so101-doctor/archive/refs/heads/main.zip mujoco==3.17.0
# Plug in and power the arm, quit LeRobot, then check it and write the twin (no arm: it still writes the twin)
$ ~/so101/bin/so101-doctor --export-mujoco ~/so101_twin
# Open the twin
$ ~/so101/bin/python -m mujoco.viewer --mjcf ~/so101_twin/scene.xml

Start here

Six steps, about five minutes. Every command is pasted into a terminal, then Enter. On a Mac: press Cmd and Space, type Terminal, press Enter. On Windows: open the Start menu, type PowerShell, press Enter.

You need Python 3.10 or newer and an internet connection. The arm is needed for step 4 only; step 5 reads it if it is plugged in and works without it.

Words used here: a twin is a simulated copy of the arm. MuJoCo is a free physics simulator. The P gain is a servo setting for how hard it pulls toward its goal: LeRobot sets 16, the factory value is 32. A register is one numbered setting stored in a servo.

  1. Check Python

    macOS or Linux
    python3 --version
    Windows (PowerShell)
    py --version

    It should print Python 3.10 or newer. If Python is missing or older, install it from python.org, open a new terminal and check again.

  2. Make a private folder for the tools

    macOS or Linux
    python3 -m venv ~/so101
    Windows (PowerShell)
    py -m venv "$HOME\so101"

    It prints nothing: that means it worked. This makes a Python virtual environment, a folder with its own copy of Python. Everything below installs into it, nothing else on your computer changes, and deleting the folder removes it all. On Debian or Ubuntu, if it says ensurepip is not available, run sudo apt install python3-venv and try again.

  3. Install so101-doctor and MuJoCo

    macOS or Linux
    ~/so101/bin/pip install https://github.com/VatoLabs/so101-doctor/archive/refs/heads/main.zip mujoco==3.17.0
    Windows (PowerShell)
    & "$HOME\so101\Scripts\pip" install https://github.com/VatoLabs/so101-doctor/archive/refs/heads/main.zip mujoco==3.17.0

    The last line should start with “Successfully installed”. A notice about upgrading pip is harmless. On Windows the & at the start of the line is needed.

  4. Check your arm

    Plug the power supply into the servo board, then the USB cable into your computer. Close any terminal that is running LeRobot (teleoperation, recording, calibration) or another script that talks to the arm. Then:

    macOS or Linux
    ~/so101/bin/so101-doctor
    Windows (PowerShell)
    & "$HOME\so101\Scripts\so101-doctor"

    The first line should say “6 of 6 servos read” and “scan complete”. Below it you get one row per servo and any warnings in plain words. A warning is not an error, and nothing on your arm was changed. No arm? Add --demo to see example output. If it finds no port or the wrong one, see Fixes.

  5. Write the twin

    macOS or Linux
    ~/so101/bin/so101-doctor --export-mujoco ~/so101_twin
    Windows (PowerShell)
    & "$HOME\so101\Scripts\so101-doctor" --export-mujoco "$HOME\so101_twin"

    With the arm plugged in it reads the P gain of joints 1 to 5 and writes the twin built for it. Near the end it says which one you got, for example “Exported the SO-101 MuJoCo twin for P 16 (read from your arm)”, and whether your servos match what the twin assumes.

    Without an arm it writes the P 16 twin, the gain LeRobot sets. If your arm runs P 32, add --twin-p 32. Give it a new or empty folder: the tool never overwrites other files.

  6. Open the twin in MuJoCo

    macOS or Linux
    ~/so101/bin/python -m mujoco.viewer --mjcf ~/so101_twin/scene.xml
    Windows (PowerShell)
    & "$HOME\so101\Scripts\python" -m mujoco.viewer --mjcf "$HOME\so101_twin\scene.xml"

    A window opens with the arm on a floor. The Control panel on the right has one slider per joint: each sets that joint’s goal, as the goal register does on the real servo. Space pauses, Backspace resets.

Checked by us: every step on Ubuntu 24.04 with Python 3.10 (in step 6 the window opened with the twin; its sliders and keys were not tried), steps 3 and 5 also with Python 3.12, and the register check on macOS. Not yet checked by us: the Windows lines, and steps 5 and 6 on macOS. If a step fails, open an issue with the line it printed.

Vato’s twin

The twin is the SO-101 model from MuJoCo Menagerie with its five arm servos replaced by a model of the real STS3215: the servo’s P loop on motor voltage, its 12 V limit, the motor’s back-EMF and a limit that stands in for the firmware’s acceleration profile. It is one plain MuJoCo file with nothing to install besides MuJoCo.

It comes in two versions, for P 16 (what LeRobot writes) and for P 32 (the servo’s factory value). so101-doctor gives you the one your arm runs.

  1. scene.xml is the arm on a floor, so101_twin.xml the arm alone.
  2. values.json and README.md list the nine servo values and where each comes from.
  3. Drive it like the servo: ctrl is the joint goal in radians. The gripper keeps Menagerie’s actuator.
  4. Angles are Menagerie’s. LeRobot’s degrees are counted from the middle of the range you swept when calibrating (wrist roll: from the pose you held; the gripper is 0 to 100, not degrees), and the twin works in radians. So the two differ by an offset per joint that depends on your arm. so101-doctor does not work that offset out yet, so do not copy joint numbers between LeRobot and the twin.

From Python: save this as try_twin.py and run it with ~/so101/bin/python try_twin.py (Windows: & "$HOME\so101\Scripts\python" try_twin.py). With the P 16 twin it prints about 0.29, -0.48, 0.41, 0.30, -0.19.

import os
import mujoco

path = os.path.expanduser("~/so101_twin/scene.xml")  # from step 5
m = mujoco.MjModel.from_xml_path(path)
d = mujoco.MjData(m)
# joint goals in rad: pan, lift, elbow, wrist flex, wrist roll
d.ctrl[:5] = [0.3, -0.5, 0.4, 0.3, -0.2]
for _ in range(6000):  # 3 s at the file's 0.5 ms step
    mujoco.mj_step(m, d)
print(d.qpos[:5].round(3))  # where the joints are now

Tip positions are computed from the joint encoders, not seen by a camera. A hold is one pose the arm moved to and rested at. P 16 measured 8 Nov 2026, P 32 on 10 Nov 2026.

One arm, bare, nothing in the gripper, one session per row. In motion at P 16 the twin tracked the joints to 1.25° RMSE (the typical error) against 2.23° for stock Menagerie, and was closer on every joint of all five teleoperation recordings replayed (same arm, recorded 2 Nov 2026, not yet replicated). Stock Menagerie is robotstudio_so101 from mujoco_menagerie at repository commit f3b6013 (23 Oct 2026).

Not checked: a second arm, a load in the gripper, the 7.4 V servo version, P gains other than 16 or 32 or different gains per joint, fast teleoperation at P 32. Scored on MuJoCo 3.17.0 (only the 2.23° for stock Menagerie in motion was computed on 4.0.0); on 4.0.0 the twin loads and one 3 s test move ended at the same joint angles.

The servo torque law is BAM’s (Rhoban, arXiv 2410.08650). The body, meshes and gripper are Menagerie’s (derived from The Robot Studio’s SO-ARM100 model), so the exported folder is Apache-2.0.

What it prints

One row per servo, then warnings in plain words. With --export-mujoco it adds a line for each servo setting that differs from what the twin assumes.

  1. The acceleration limit the firmware puts on its internal target, from registers 41 and 85, and the shortest time that allows for a 60° move.
  2. Firmware, supply voltage against the servo’s own limits, temperature, gains and fault bits.
  3. Warnings when register 85 caps the acceleration you asked for, joints are set up differently, the supply is above a servo’s voltage setting, a servo is missing or a position is outside one turn.

If something is off

What you might see, and what to do about it.

You seeWhat it means and what to do
“No USB serial port found”The board is not seen. Check the USB cable and the power supply, then run it again. --list-ports shows what the computer sees.
It lists several ports and asks for --portMore than one servo board is plugged in, or no port looks like the usual board (USB vendor 1a86). Run it again with the arm’s port, for example --port /dev/ttyACM0 (Linux), --port /dev/cu.usbmodem... (Mac) or --port COM3 (Windows). --list-ports shows the names.
“Permission denied” on LinuxYour user is not allowed to open serial ports. Run sudo usermod -aG dialout $USER (it adds your user to the group that may use them), then log out and back in.
The port is busy, or no servo answersQuit LeRobot, teleoperation and calibration scripts: only one program can use the port. Check that the servos have power; USB alone does not power them.
Acceleration 0 on every jointYou just powered the arm. That register goes back to 0 at every power-on and LeRobot writes 254 when it connects. Connect with LeRobot once, close it, run so101-doctor again.
“capped by Maximum_Acceleration”Register 85 limits that joint’s acceleration below what register 41 asks for, so the joint moves slower than the others. LeRobot writes 254 to both when it connects.
P 16 on some joints and 32 on othersNot tested with the twin. You get the P 16 twin and a note. Set joints 1 to 5 to the same value, 16 or 32.
About 7 V instead of 12 VYou have the 7.4 V servo version. The register check works; the twin is not made for it yet.
“holds the twin for P 32, not P 16: pass a new folder”, or the folder is not emptyThe tool never overwrites other files. Give --export-mujoco a new folder name.
pip cannot find mujoco 3.17.0Your Python is older than 3.10. Install a newer Python and start again from step 2.
On a Mac, your own script with launch_passive failsRun that script with ~/so101/bin/mjpython script.py instead of python. The viewer command in step 6 does not need this.

Why the acceleration matters

The STS3215 does not drive straight to the goal you send. It moves an internal target toward the goal at a constant acceleration, braking in time to stop on it, and the position loop follows that target. The acceleration is a = 100 steps/s² × min(register 41, register 85), with register 41 at 0 acting as 50. A simulator without this profile has the servo chase the goal itself, which the real one does not do.

Read only

so101-doctor can send the servos two instructions, PING and READ, and nothing else. It has no way to write a register, so it cannot move the arm, change a setting or switch torque on or off. Its tests check that only those two are ever sent. If LeRobot or another script has the port open, close it first. Source and tests: VatoLabs/so101-doctor.

Facts
- Read only: the tool sends PING and READ packets and nothing else. It cannot move the arm, write a register or switch torque.
- It needs the serial port to itself: ask the user to quit LeRobot first. One board with USB vendor 1a86 is picked automatically; otherwise pass --port.
- --export-mujoco reads the P gain of servos 1 to 5 and writes the twin for it (16 or 32). No arm: the P 16 twin. --twin-p 16 or --twin-p 32 chooses by hand.
- --json prints one JSON object: version, source, complete, bus_error, servos, findings (level, text) and, with --export-mujoco, twin (exported, p, p_source, checked, reason, match, mismatches, mixed_p, assumes). p_source is arm, option (--twin-p), default (no arm read, mixed gains, or a P other than 16 or 32) or demo.
- Exit codes: 0 report printed, 1 nothing could be read (port busy, no servo answered, or no port found), 2 bad command line or an export folder that holds other files or the other P's twin (the same twin again is left as it is and is not an error), 3 with --strict when there is a warning or the scan is incomplete. With --export-mujoco and no port found the twin is still written and the exit code is 0.
- The viewer opens a window and blocks. Without a display, load the file with mujoco.MjModel.from_xml_path("scene.xml") and step it; ctrl = joint goal in rad.
- No arm connected: skip the plug-in step. The export needs no --demo; use --demo only to show example output.
- A freshly powered arm reads Acceleration 0 on every joint until LeRobot has connected once. That is not a fault.
- Do not write servo registers to make the check pass unless the owner asks for it.
- Accuracy, do not overstate it: one arm, bare, one session per gain, not yet replicated. Tip error at rest 6.4 mm at P 16 (180 holds, 8 Nov 2026) and 3.7 mm at P 32 (164 holds, 10 Nov 2026), against 15.2 and 7.7 mm for stock Menagerie.
