so101-doctor

A free tool that reads every register of the six STS3215 servos on an SO-101 arm and tells you what they really do. It only reads.

# 1. In a terminal (macOS or Linux, Python 3.9 or newer), make a home for it
$ python3 -m venv ~/so101-doctor
# 2. Install it there
$ ~/so101-doctor/bin/pip install https://github.com/VatoLabs/so101-doctor/archive/refs/heads/main.zip
# 3. Try it with no arm (example values)
$ ~/so101-doctor/bin/so101-doctor --demo
# 4. Plug in the arm, power the servos, then
$ ~/so101-doctor/bin/so101-doctor

Close LeRobot first if it is running. Windows steps and options: README.

What it prints

One row per servo, then warnings in plain words.

  1. The acceleration the firmware really uses, from registers 41 and 85, and the shortest time that allows for a 60° move.
  2. Firmware, supply voltage against the servo’s own limits, temperature, gains and fault bits.
  3. Warnings when register 85 caps the acceleration you asked for, joints are set up differently, the supply is above a servo’s voltage setting, a servo is missing or a position is outside its limits.

Why the acceleration matters

The STS3215 does not drive straight to the goal you send. It moves an internal target toward the goal at a constant acceleration, braking in time to stop on it, and the position loop follows that target. The acceleration is a = 100 steps/s² × min(register 41, register 85), with register 41 at 0 acting as 50. A simulator that ignores this is wrong on every move.

Read only

so101-doctor can send the servos two instructions, PING and READ, and nothing else. It has no way to write a register, so it cannot move the arm, change a setting or switch torque on or off. Its tests check that only those two are ever sent. If LeRobot or another script has the port open, close it first.
